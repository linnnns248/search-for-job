# v0.3.0 公司官网采集计划

## 版本目标

在不改变现有公开网页使用方式的前提下，把用户提供的公司招聘官网接入本地采集端，生成与 Boss 岗位一致的结构化记录，并安全合并到 `public/data/jobs.json`。

本版本解决“官网来源可配置、可扩展、可测试地接入”的问题。它不是一个尝试适配所有网站的通用爬虫；每个招聘站必须通过明确的适配器或受控的声明式规则接入。

## 范围

### 包含

- 新增版本化的官网来源配置，支持启用/停用、公司名称、公司规模、招聘页链接和适配器类型。
- 建立统一的官网适配器接口，输出来源岗位的标准候选字段。
- 首批支持两类接入方式：
  - 页面包含 `JobPosting` JSON-LD 的标准结构化招聘页。
  - 可通过配置选择器描述的普通列表页/详情页。
- 对必须执行 JavaScript 或使用公开招聘 API 的站点保留专用适配器扩展点；只有拿到真实官网后才实现对应适配器。
- 官网岗位按城市、岗位名称、求职类型、学历和已披露薪资执行配置化过滤。
- 官网未公开薪资时记录为“未披露”，不推测薪资。
- 生成稳定的官网岗位 ID，并与历史官网记录做同源去重。
- 对 Boss 与官网的相似岗位做保守的跨来源合并；无法高置信匹配时保留为两条，避免误合并。
- 单个官网扫描失败或返回空结果时保留原数据，并记录可诊断的运行结果。
- 为适配器、过滤、标准化、合并和失败保护补充自动测试与固定 HTML 样例。
- 更新安装、配置、隐私和换电脑接管文档。

### 不包含

- 自动提交和推送 GitHub；该能力仍属于 `v0.4.0`。
- 登录后才能访问的公司内部招聘系统。
- 绕过验证码、访问限制、机器人验证或网站安全策略。
- 服务端数据库、用户登录、简历分析、投递管理和个人备注。
- 未经验证就把单次未发现的岗位直接标记为下架。

## 数据流

```text
config/official-sites.json
        ↓
官网采集调度器
        ↓
按来源选择适配器
        ↓
列表发现 → 详情读取 → 字段解析
        ↓
配置条件过滤 → 标准化 → 同源去重
        ↓
与 Boss 数据保守合并
        ↓
public/data/jobs.json
```

账号、Cookie、原始页面快照和运行凭据不得进入公开数据或 Git 仓库。

## 配置草案

计划新增 `config/official-sites.json`，结构如下：

```json
{
  "schemaVersion": 1,
  "sources": [
    {
      "id": "example-company",
      "company": "示例公司",
      "companySize": "1000-9999人",
      "companySizeMin": 1000,
      "careersUrl": "https://careers.example.com/jobs",
      "adapter": "json-ld",
      "enabled": true
    }
  ]
}
```

站点专属选择器、公开 API 路径或分页参数放在适配器配置中，不写入核心采集逻辑。公司规模以用户确认的公开信息为准，并保留来源说明；不从招聘文案中猜测。

## 适配器协议

每个适配器至少实现：

- `discover`：分页发现岗位链接或来源岗位 ID。
- `fetchDetail`：读取单个岗位的公开详情。
- `normalize`：映射为统一候选字段。
- `sourceKey`：生成同一官网内稳定的来源标识。
- `scanResult`：返回成功、部分成功、空结果或失败，并附带非敏感诊断信息。

统一候选字段包含公司、公司规模、岗位名称、岗位描述、薪资、城市、学历、求职类型、来源名称和公开链接。写入公开数据前只保留现有 `JobRecord` 白名单字段。

## 过滤与薪资口径

- 城市、岗位名称、求职类型、学历、薪资和公司规模继续读取现有公开配置，避免复制业务规则。
- 官网明确披露薪资时，继续执行月薪下限 10K 的条件。
- 官网未披露薪资时，暂定允许保留并显示“未披露”，因为不能可靠判断其是否低于 10K；该例外必须在页面和下载数据中保持可识别。
- 如果用户决定所有来源都必须严格满足 10K，则把未披露薪资的官网岗位改为不发布，无需改适配器。
- 官网没有明确学历或求职类型时不猜测；是否允许保留作为首次真实站点接入前的确认项。

## 去重策略

1. 同一官网优先使用官网岗位 ID 或规范化详情链接生成稳定 ID。
2. 同源重复记录按稳定 ID 合并，并保留首次发现和最后发现时间。
3. 跨来源仅在规范化公司名、岗位名、城市和岗位描述均达到高置信匹配时合并来源数组。
4. 不能确定是否为同一岗位时保留两条；宁可重复，不误删岗位。

## 需要用户提供的内容

首批接入前，每家公司需要：

- 公司名称。
- 官方招聘首页或职位列表页链接，不是搜索引擎结果链接。
- 已知的公司规模；如果不确定，可先提供公开依据链接后再确认。
- 是否只采集成都岗位，还是该官网其他地点也需要保留。

不需要提供公司官网账号、密码、Cookie、验证码或任何个人信息。

## 提前卡点

- 不同公司可能使用北森、Moka、猎聘企业版、自建站点等不同系统，首批链接决定需要哪些专用适配器。
- 部分招聘站完全依赖 JavaScript，普通 HTML 请求拿不到岗位，需要使用公开接口或受控浏览器适配器。
- 官网常常不公开薪资、学历或公司规模，缺失字段的发布口径需要在首次真实接入前确认。
- 官网可能没有稳定岗位 ID；这类站点必须用规范化链接和内容指纹组合，避免每日产生重复记录。
- 网站结构变化不可避免，因此每个适配器必须有独立测试样例和失败保护。

## 完成定义

`v0.3.0` 只有在以下条件全部满足后才发布标签：

- 至少一个用户提供的真实公司官网完成端到端采集。
- Boss 与官网岗位可以共存、筛选、查看和下载。
- 配置字段可调整，新增同类官网不需要修改核心合并逻辑。
- 任何单一来源失败都不会清空或损坏已有岗位数据。
- 公开构建产物不包含登录态、令牌、原始私密页面或个人数据。
- 自动测试、数据校验、扩展构建和网页构建通过。
